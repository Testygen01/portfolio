# Auditing 160 Knowledge Base Documents for Accessibility
`Accessibility` `Technical Writing` `Quality Assurance` `Knowledge Management`

## Overview

Over about two months, alongside my other rotation work and meetings, I audited roughly 160 articles in DoIT's internal knowledge base platform and remediated the accessibility issues I found, so the documentation worked for everyone, including people using assistive technologies.

## The problem

The knowledge base had grown through many contributors with varying accessibility awareness, and the inconsistency was a real barrier, not a cosmetic issue. The recurring problems were concrete: inconsistent heading levels, tables without proper header cells, links whose text did not describe where they led, language that was harder than it needed to be, and code samples wrapped in `<pre>` tags instead of proper code formatting. Each issue was small; across 160 articles they added up.

## What I did

I worked through the articles systematically with a repeatable pass: read for structure, check formatting consistency, verify accessibility, fix what was broken, and move on. Across the collection I corrected the recurring issue types above and standardized formatting where it had drifted, so the knowledge base reads as one coherent resource instead of 160 individual efforts. When the audit was complete, I presented the work to the team in a standup, walking through what I had found and fixed, and documented a reference framework so new documents could be written accessibly from the beginning rather than repaired afterward.

## Result and scope

About 160 articles reviewed and remediated over roughly two months, interleaved with my other project work and meetings. The knowledge base came out more consistent and more usable, and the reference framework turned a one-time cleanup into a durable standard: each new document starts from an accessible baseline instead of reintroducing the old inconsistencies.

## What this shows

This case treats accessibility as engineering work, not a checkbox exercise. I found the recurring patterns, fixed them at scale across 160 articles, and then changed the process so the problems would stop being created. It also shows sustained execution: two months of steady audit work carried alongside everything else on my plate.
