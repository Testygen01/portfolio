# AWS Innovation Sandbox (ISB) Platform Development

## Overview

The AWS Innovation Sandbox (ISB) project was designed to provide researchers and faculty with a secure cloud environment for experimentation while maintaining governance and operational controls. During my rotation, I contributed to discovery activities, infrastructure planning, and deployment workflows supporting the development of the solution.

## Environment

- Amazon Web Services (AWS)
- Terraform
- Git
- GitLab
- VScode
- AWS Control Tower
- Research Computing Stakeholders

## Problem

Researchers required a cloud environment that enabled innovation and experimentation while adhering to institutional governance and security requirements.

The challenge was balancing flexibility for end users with the controls necessary to safely manage their cloud resources.

## Actions Taken

- Participated in the project discovery and requirements gathering
- Supported Infrastructure-as-Code workflows using Terraform
- Contributed to Git and GitLab-based deployment processess
- Assisted with deployment activities in an ITE environment
- Documented project milestones and technical roadblocks
- Captured lessons learned surrounding AWS Control Tower constraints and template limitations

## Outcome

There were multiple technical roadblocks in this project. The biggest is that AWS do not currently expose an API endpoint for terraform for creating a SAML 2.0 application used for managing the cloud sandbox accounts.

Aside from these technical roadblocks, much of the project progressed with a clearer understanding of architectural limitations affecting the implementation. 

Most of the ground work for this project was completed during my time with the cloud team. Post rotation, I followed up with them and got confirmatin of a complete proof of concept work.

## Key Taakeaways

This project provided hands-on exposure to cloud architecture, infrastructure-as-Code practices, stakeholder discovery, vendor relations, and the challenges of designing governed cloud envrionments.

The biggest learning moment for me was the multiple meetings conducted with the vendor to clearly define the capabilities of the ISB solution. AWS assumed we will use their cloud technologies to implement the ISB, however, we are a 100% terraform environment and that caused some architectural headaches. 

With this project, I learned that a proposed solution is not always as straightforward as the stakeholders and vendors might expect. There are a multitude of considerations such as identity, compute, and governance that must respect institutional requirements.
